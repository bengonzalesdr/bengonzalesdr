### 04 — how I work

I like tools I can **inspect, customize, and understand**. I would rather know why a system behaves the way it does than stack abstractions on top of a problem until it disappears from view.

A lot of my work sits between disciplines: front end, back end, databases, hosting, maintenance, client workflow, and the boring details that decide whether software is actually pleasant to use six months later.

There are always more layers underneath.
